## 离线基准

环境为同一台 Windows / Python 3.13。两个角色轮流发言，每次固定返回 1000 个 ASCII 字符，并上报 1 个输出 token，以输出上限精确控制回合数。模型调用为本地函数，不访问外部 API。每次使用独立临时业务库；下表使用内存 checkpointer，以比较业务存储和编排开销。计时包含执行权获取和完整推进循环，不包含初始建库。

每种配置运行两次，表内耗时为算术平均；MB 使用十进制单位。修改前数据在改动生产代码前取得，两组均使用同一个基准脚本。

| 回合数 | 修改前平均耗时 | 修改后平均耗时 | 耗时降低 | 修改前业务库 | 修改后业务库 | 空间减少 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 40 | 11.981 s | 7.231 s | 39.6% | 7.086 MB | 2.150 MB | 69.7% |
| 80 | 34.471 s | 14.581 s | 57.7% | 26.370 MB | 7.516 MB | 71.5% |

原始耗时（秒）：

- 40 回合：修改前 `13.218 / 10.744`，修改后 `6.137 / 8.325`。
- 80 回合：修改前 `38.463 / 30.479`，修改后 `15.350 / 13.812`。

80 回合前后均产生 80 次模型调用、80 条发言及 241 条操作记录；最终对话 payload 均为 97,430 字节。操作快照副本从 12,040,944 个字符降为 0；操作输入合计从约 13.21 百万字符降至约 6.67 百万字符。空间变化来自消除重复数据，而不是减少发言或省略调用记录。

复现命令，在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe scripts/benchmark_orchestration.py --turns 40 80 --repeat 2
```

脚本输出逐次 JSON 数据，并校验模型调用次数、发言数、用量和最终暂停状态。若要把文件检查点开销纳入测量，使用 `--checkpointer sqlite`；该模式不应与上表的内存检查点数据直接比较。所有测试文件在临时目录内创建并清理。

# 图形化多 Agent 扩展：计划核对与验证

实施日期：2026-10-02。实施分支：`graph`，由本地 `main@29da95a82103bd068aa53fd0798711a731958cfa` 创建。依赖版本未升级。

## 计划核对

`graphical-multi-agent-langgraph-plan.md` 对基线能力的描述与代码吻合。画板权限拓扑与 LangGraph 执行流程分开：动态 Agent 是新业务实例，复用编译后的有限激活图，不修改正在执行的图定义。每个实例有独立 thread；协调器与系统辅助使用各自 thread，检查点继续 `durability="sync"`。确定的业务结果优先于检查点，恢复不会因为缺一个图节点回执就重复请求模型。依据：[Graph API](https://docs.langchain.com/oss/python/langgraph/graph-api)、[Persistence](https://docs.langchain.com/oss/python/langgraph/persistence)。

实施时补充并落实了以下约束：

- 角色、团队保存要求 `base_version`；启动只允许根节点，冻结角色与配置版本。
- 两种连线独立校验；混合环合法，有向环、多父节点和同类型重复边拒绝。
- 明确区分角色模板、节点、实例、任务、激活、操作和调用尝试。相同名字或模板不能代表同实例。
- 临时角色工具缺省继承，显式 `[]` 禁用原生工具；模型只能引用服务器已注册并由父任务授权的配置。
- `all` / `any_success` 采用持久业务等待，时限单独设置。等待释放执行与进程名额；全部失败或取消也能唤醒父任务。
- 已知结果在达到激活次数或剩余预算边界后仍能安全提交；提交回执不再申请新的模型预算。
- 全局额度由运行账本实时限制；显式角色／请求任务额度约束子树。用户延长全局额度不会被旧的隐式额度快照阻挡。
- 辅助操作与 Agent 共用资源准入。重复辅助请求不能重入同一图，也不能破坏首个请求的回执。
- 暂停、完成、删除使执行权失效并收拢任务与辅助调用；未退出时返回可重试的状态冲突，保留数据。
- 运行库通过跨进程文件锁限定单应用进程。首次增量迁移前，对已有业务库建立 SQLite 一致备份。
- 普通群聊选员合并为仓储的有限选员与 DispatchGraph 调度；不另建 RoomChoiceGraph。系统辅助仍使用独立有限图，保持输入范围、回合上限和回执提交合同。

## 保留的实际边界

- 业务库与检查点库仍没有跨库原子事务，外部工具副作用不能保证恰好一次。结果不确定时暂停并要求明确重试。
- DSH 进程回收后以新 session、授权快照和命令回执重建；文件保留，不承诺完整私有上下文恢复。
- 原生文件／进程权限依托既有 DSH 宿主策略；独立工作目录和工具白名单不等于操作系统级文件隔离。
- 运行时间恢复以最近持久进度为准；每秒进度记录之前的崩溃残余无法精确恢复。暂停和停机不计入。
- 已知用量与预留不代表精确费用封顶；服务商漏报、压缩和取消窗口仍可能产生不确定消耗。
- 首版为单应用进程、HTTP 轮询、非重叠连通群聊；多父 DAG、多机调度和多人编辑仍按原计划不纳入首版。
- 2026-10-02 的验证未启用真实收费 API；2026-10-03 经用户授权增加的真实测试单独记录于下节。协议验证不保证任意真实模型和开放目标的规划效果。

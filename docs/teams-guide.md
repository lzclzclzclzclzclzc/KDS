# 团队画板与运行观察台

从首页进入「图形团队」，或打开 `/teams`。旧群聊和旧历史继续保留；团队运行使用独立的配置与执行记录。

## 定义角色与构建团队

1. 在左侧角色库新建角色，填写职责、提示词、模型配置引用与默认预算；从服务器启用的有限工具目录中勾选权限，也可「全选可用工具」。团队编排工具按任务权限自动提供，不混入人工工具列表。模型配置需要在服务器注册。
2. 点击「放到画板」生成独立节点。同一个角色可重复使用，例如分别创建「总体校验」和「细节校验」。两者固定引用角色版本，但具有独立实例、任务和 DSH 会话。
3. 点击「父子任务」，依次点击父节点和子节点，建立有向委派关系。每个子节点最多有一个父节点，任务关系不能形成有向环。连线只定义委派权限，不立即运行节点。
4. 点击「群聊连接」，依次点击两个节点。双向连线按连通分量组成房间：`A ↔ B ↔ C` 是一个三人群聊。**同一对节点只能保留一种连接**，不能同时建立任务边和群聊边；改变关系时可编辑原连线类型，或先删除再连接。群聊连接不会授权互相派发任务，也不参与任务关系的有向环校验。
5. 点击节点或连线编辑属性；点击空白处或按 `Esc` 查看共享背景、群聊预览和内容白板设置。内容白板保存共同产出物，和团队拓扑画板分别管理。启用白板后，可选择 Markdown / HTML 及允许编辑的节点。

画板支持拖动节点、空白拖动框选、`Shift + 点击` 增减选择、`Delete` 删除、`Ctrl + Z` 撤销、`Ctrl + Shift + Z` 重做、树形布局与适配视图。按住空格拖动平移，滚轮缩放。快捷键 `V` 为选择、`T` 为父子任务、`C` 为群聊连接、`F` 为适配视图。节点和连线也可以通过键盘聚焦并使用 `Enter` 选择或连接。

编辑画板与运行观察台的左右边栏均有可拖动分隔条。分隔条获得焦点后可用方向键微调、`Shift + 方向键` 加速，`Home` / `End` 调到最小 / 最大宽度；两个模式分别记住宽度。

九个论文预设角色直接显示在左侧角色栏，附职责说明和可打开的论文来源。浏览角色库不会自动写入数据库；首次点击编辑或「放到画板」时才按需保存普通角色模板，已有等价模板会优先复用。同一预设的等价保存副本合并显示，提示词、工具、模型、预算、权限或来源等实际配置不同的角色仍独立保留，不会只按同名合并。

「选择预设团队」先展示只读预览。已保存团队的下拉选择与「预览版本」可查看当前及历史配置版本；运行列表中的「预览配置」展示该次运行冻结的角色与拓扑。预览可点击节点查看完整提示词、工具权限和来源，保留当前未保存草稿，不创建角色或团队，也不调用模型。明确点击「使用此预设团队」或「载入此版本」后才进入编辑；历史版本或运行配置载入为独立草稿。也可先预览基础协作示例，再明确使用。

使用后可编辑并保存自己的版本，来源会随配置保留。预设团队的建议运行额度会显示在启动对话框中。

「从旧配置建立团队」建立新角色模板和群聊连接，不补造旧任务或修改旧数据。导出 JSON 包含当前拓扑与所引用的角色版本；导入完整文件时会建立独立的角色模板与团队配置。

## 保存版本与启动

「保存版本」保存节点位置、连线、角色版本引用、共享背景及白板权限。角色更新会建立新角色版本，节点原有的版本引用继续保留，可以在节点属性中明确改用其他版本。

「启动团队」要求填写工作目标，并选择至少一个入口根节点。单节点团队也可运行。未选择的根节点保持待命，只有收到合法委派或讨论机会时才处理工作。

启动时冻结配置、角色版本和既有关系。在观察台点击「编辑下次运行配置」会修改草稿或建立新配置版本，下一次启动时才能应用。运行中 Agent 自主创建的子节点作为本次运行的增量记录展示，不改写冻结的配置。

角色与运行的单次输出上限可以留空，或填写 `0` 表示不限；填写正整数才设置单次限制。空角色额度不能放宽已经有限的父任务或运行额度。

总输出 token 与运行时长仍至少设置一项有限上限；界面的 `0` 表示该项不限。并发 Agent 数量、实例数、任务数与层级均有限。等待子任务仍计入运行时长，但不占模型执行名额；人工暂停与停机期间不计入运行时长。预算显示已知消耗，外部服务漏报或调用取消窗口可能造成暂时不确定的用量。

启动与「调整运行上限」均可修改「预留总结输出预算」，默认 1024，必须填写正整数。该预算也包含模型思考消耗；总输出有限时必须低于总额度，为任务执行保留预算。仅按时长限制运行时仍可设置总结预留预算。

## 观察任务、群聊和 Agent

左侧导航可切换总览、任务树、群聊、独立 Agent、系统辅助与产出物。切换页面不会暂停后台执行。搜索用于筛选房间和 Agent；未读计数和异常标记帮助定位需要关注的实例。

任务树展示委派关系和正式交付，可从记录跳到子任务、父任务或对应 Agent。Agent 视图展示其任务、公开输入、交付、工具过程和子 Agent；工具日志按实例、任务与激活关联，只展示操作和结果。群聊视图只显示所选房间的消息。

向已有任务的直接子节点继续合法委派时，新任务进入该实例的待办队列。同一实例逐个执行自己的任务，独立实例可在全局并发上限内并行；忙碌本身不表示派发失败。

Agent 查询自己派发的子任务时，如果本次查询中还有任务未完成，系统会自动让它等待并释放执行名额，让子任务继续工作。本次查询的子任务全部结束后，父 Agent 再继续处理正式结果；期间排队的补充信息会保留到下一次交付。

运行时创建的节点标为「动态」，详情说明创建者和角色来源。临时角色可以明确保存到角色库；未经保存，不会自动成为可复用模板。

总览的暂停提示会列出失败或待核对任务的角色与错误摘要，可直接跳到任务记录定位原因。工具过程按独立调用记录展示，相同参数的多次合法调用分别保留。

「产出物」展示内容白板与版本。HTML 白板在隔离环境中预览，不能执行脚本或访问父页面；也可下载白板源文。多个 Agent 同时修改白板时，版本冲突会使后提交者读取新版本并重新规划，避免静默覆盖。

## 人工消息和全局控制

向单个 Agent 发送的内容仅作为补充信息排队，界面显示「已排队 · 待下次激活读取」。它不会建立任务、抢占当前执行、解除子任务等待，也不会重新打开已经交付的任务。待命实例将消息保留到后续合法激活。界面没有单 Agent 手动派任务或取消任务按钮。

向群聊发送消息会触发该房间的有限讨论。普通 Agent 回复不会无限引发新的讨论；消息和正式任务结果分别管理。

顶部「暂停」「继续」「调整运行上限」「总结并完成」控制整场运行。达到预算或任务全部交付时，运行暂停供人工查看；确定的执行失败记入该任务，其他独立任务继续。不确定外部调用或关键存储错误会暂停整场运行。任务完成不等于会话已经人工完成。

若外部调用已发生却没有确定结果，相关任务标为待核对并暂停。点击全局「继续」时，需要先核对可能已发生的文件或工具副作用，再明确允许重试。系统不会透明重跑未知写操作。

「总结并完成」会收拢正在执行的任务，冻结总结输入，并使用预留预算生成总结；也可选择「只保存现有结果完成」。总结失败仍保留人工完成状态和错误。完成后的运行只读，创建新工作目标需从画板启动新的运行。

## 系统辅助与离线验证

「系统辅助」提供配置建议、意愿评分和投票，显示结果、错误与用量。辅助调用与 Agent 共用预算和并发名额；总结、格式修正及所有真实 Agent 请求均通过 DSH，失败时不会静默切换到直连模型。

`LLM_MOCK=true` 是明确的离线入口，使用模拟执行器，适合不调用收费模型的体验和验证。浏览器离线验收脚本 `tests/test_team_ui.cjs` 使用真实页面资源和模拟 HTTP；`tests/test_team_service_ui.cjs` 需要明确设置 `KDS_TEAM_UI_URL`，指向使用临时数据库和离线执行器的真实服务。它验证 REST、SQLite、LangGraph 与浏览器联动，不代表已验证真实收费模型的输出效果。

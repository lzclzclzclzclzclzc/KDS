# 论文参考角色与团队预设

更新日期：2026-10-03。预设在 `/teams` 中直接显示，只有明确使用时才写入角色库或建立团队，不会自动运行。角色预设会复用未归档且配置等价的现有模板；同一团队预设再次使用仍建立独立团队，但相同角色可共享模板。提示词、工具权限、模型、预算或可见性不同的角色不会仅凭同名合并，历史版本引用保持原样。来源随版本保存、导出和导入。

预览预设、已保存团队或历史运行只读取拓扑、固定角色版本与论文来源，不建立配置、不启动执行。历史配置可明确载入成独立草稿，再按需编辑和保存。

## 参考依据与改编

- [CAMEL，NeurIPS 2023](https://arxiv.org/abs/2303.17760)：参考任务指定与任务执行的双角色分工。KDS 使用父子任务、等待和正式结果代替原论文的角色扮演对话循环。
- [AutoGen，COLM 2024](https://arxiv.org/abs/2308.08155)：参考可定制角色、工具执行反馈与组合会话。KDS 的协调／执行／审阅分工是针对本应用设计的配置，不是论文规定的唯一团队。
- [MetaGPT，ICLR 2024](https://arxiv.org/abs/2308.00352)：参考需求、架构、任务管理、工程与质量验证职责，以及结构化 SOP 交接。KDS 用嵌套任务传递依赖并回传验证结果，没有复现其全局发布订阅池。
- [Improving Factuality and Reasoning in Language Models through Multiagent Debate，ICML 2024](https://proceedings.mlr.press/v235/du24e.html)：参考多个实例独立解答、交换结果并修正答案。KDS 增加协调员与反例角色，限定一次交叉核查；不承诺复现论文成绩，也不将多数共识等同于事实正确。

提示词是针对 KDS 编写的中文工作指令，并非论文提示词的逐字拷贝。任务规则、有限轮次和工具权限以 KDS 的执行合同为准。

## 通用角色

| 角色 | 职责 | 参考 |
| --- | --- | --- |
| 任务协调员 | 拆解依赖、派发工作、检查正式结果 | AutoGen、MetaGPT |
| 需求分析员 | 明确输入输出、边界与验收条件 | CAMEL、MetaGPT |
| 资料研究员 | 检索资料并保留可追溯依据 | AutoGen |
| 方案设计员 | 设计方案、接口与执行步骤 | MetaGPT |
| 执行实现员 | 生成代码、文档或计算产出并验证 | CAMEL、AutoGen、MetaGPT |
| 结果审阅员 | 独立核查结果、遗漏和证据 | AutoGen、多 Agent 辩论 |
| 质量验证员 | 设计并执行具体检查，报告真实结果 | MetaGPT、AutoGen |
| 反例质询员 | 查找反例、替代解释与隐含假设 | 多 Agent 辩论 |
| 证据整合员 | 整理来源、解决冲突、保留不确定性 | AutoGen、多 Agent 辩论 |

工具权限是预设建议与服务器有限目录的交集。没有工具的角色仍可分析已提供资料，但不能宣称已执行工具。单次输出上限留空；整场运行和父任务的显式额度仍限制实际消耗。每次 DSH 请求还受服务器配置的请求上限、步骤和时间限制。

## 团队配置

| 团队 | 任务关系 | 群聊关系 | 工作流程 |
| --- | --- | --- | --- |
| CAMEL · 目标澄清与执行 | 任务澄清 → 方案执行 | 无 | 明确需求和验收条件，委派执行，核对结果 |
| AutoGen · 执行与审阅 | 工作协调 → 执行实现；工作协调 → 独立审阅 | 执行实现 ↔ 独立审阅 | 先执行，正式结果供独立审阅，最多一次修改 |
| MetaGPT · 结构化交接 | 需求分析 → 方案设计 → 任务协调 → 执行实现 → 质量验证 | 无 | 五阶段结构化交接，质量结果逐层回传 |
| 多 Agent 辩论 · 交叉核查 | 证据协调 → 推理 A／推理 B／反例质询 | 推理 A ↔ 推理 B ↔ 反例质询 | 第一轮独立回答，第二轮交叉核查，按证据整合分歧 |

每对节点只有一种连接。任务有向关系仍是树／森林；群聊边按连通分量解释，普通发言不会自动无限繁殖讨论。团队预设的建议上限是总输出 30,000 tokens、活跃运行 600 秒、执行／进程并发 2，并从总额度预留 1,024 tokens 总结；启动前可以调整。大型目标应先缩小范围或提高明确的额度。

跨实例交接文件时，需传递实际路径和必要内容，并验证接收实例是否有读取权限；不能只凭文件名假设双方共享工作目录。
